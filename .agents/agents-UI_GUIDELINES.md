# Patronus — UI & UX Guidelines

## 1. Visual Direction

Patronus should feel like a magical communication tool.

Visual inspiration:

- Ancient spellbooks
- Parchment
- Candlelight
- Stars
- Night skies
- Magical letters
- Wax seals
- Wands
- Enchanted objects

The design should be atmospheric without becoming difficult to use.

---

# 2. Overall Mood

The desired feeling is:

> "I am opening a magical object that lets me communicate with someone I care about."

Not:

> "I am using a normal chat application with Harry Potter colors."

---

# 3. Typography

Typography should feel magical but remain highly readable.

Use decorative typography selectively for:

- Logo
- Major headings
- Section titles

Use a highly readable font for:

- Messages
- Forms
- Buttons
- Navigation
- Timestamps

Never sacrifice readability for theme.

---

# 4. Colors

Use a dark magical foundation with warm parchment-like surfaces and subtle golden/magical accents.

Avoid using too many colors.

The interface should feel cohesive.

---

# 5. Cards

Cards should feel like magical objects rather than generic SaaS cards.

Possible visual details:

- Subtle borders
- Paper textures
- Soft shadows
- Small decorative elements
- Wax-seal motifs

Do not add decoration to every element.

---

# 6. Animations

Animations should feel magical and intentional.

Good examples:

- Message gently appearing
- Ink-writing effect
- Small magical particles
- Subtle glow
- Page transition
- Wand/cast interaction

Avoid:

- Constant particle effects
- Excessive bouncing
- Long animations
- Animations that interfere with reading
- Heavy effects on every click

Animations should enhance the experience, not slow it down.

---

# 7. Messaging UI

Messages should remain easy to scan.

Avoid turning every message into a large decorative parchment card.

Use subtle magical styling while maintaining conventional chat usability.

The sender, message content, and timestamp should remain immediately understandable.

---

# 8. Primary Action

The main message action can be:

> **CAST**

or:

> **SEND PATRONUS**

"CAST" is preferred if the context is already obvious.

Example:

```text
Write a Patronus...

                         [CAST ✨]
```

---

# 9. Empty States

Empty states should be thematic.

Example:

> 🦉  
> No Patronuses have arrived yet.  
> Your Circle is waiting for its first message.

Avoid generic:

> "No data found."

---

# 10. Loading States

Loading states can use magical language.

Example:

> Consulting the spellbook...

or:

> Summoning your Circle...

Keep loading messages short.

---

# 11. Error States

Errors should remain understandable.

Do not sacrifice clarity for theme.

Good:

> We couldn't join this Circle.  
> Please check your Circle Code and try again.

Bad:

> The ancient magic has rejected your summoning.

Theme can be secondary to usability.

---

# 12. Responsive Design

Design mobile-first.

Important mobile considerations:

- Large touch targets
- Comfortable message composer
- No horizontal overflow
- Keyboard-friendly forms
- Sticky composer where appropriate
- Readable message text
- Accessible contrast

---

# 13. Accessibility

Maintain:

- Keyboard navigation
- Visible focus states
- Semantic HTML
- Accessible button labels
- Sufficient contrast
- Reduced-motion consideration

Animations should respect:

```text
prefers-reduced-motion
```

where practical.

---

# 14. Harry Potter-Inspired Assets

Do not depend on copyrighted movie screenshots, official logos, character images, or other proprietary assets.

Use original or appropriately licensed assets.

The visual language should communicate "magical wizarding world" without requiring official Harry Potter assets.
